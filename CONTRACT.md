# Forma API contract

Same origin SPA + JSON API. All JSON errors `{error: string}` with correct status. Cookie credentials; unsafe requests send `X-Quiz-Request: 1`, Origin checked against APP_ORIGIN when present. API timestamps ISO UTC. Stable ids via UUID. Participant APIs conceal private answer keys until an explicitly permitted question check or completion; feedback exposes human-readable answer texts only as described below.

## Interface language and administrator identity
UI languages are `ru` and `kk`. An explicit selection in `localStorage` key `forma-language` takes precedence; otherwise choose the first supported language from the browser languages, falling back to `ru`. Language changes rerender interface text without recreating an active attempt. Quiz/question/option/group/student content and expected-answer texts remain in their original language.

Administrator display is the translated role `Администратор` and fixed proper name `Abzal Nurlanuly`; this does not rename login credentials. Setup creates the first administrator only. CLI provisioning rejects a different second username once an administrator exists; `--username <existing> --reset-password` updates that account and revokes its sessions.

## Quiz author model
`{id,slug,title,description,intro,outro,status:'draft'|'published'|'closed',settings:{requireName:true,rosterEnabled:false,requireStudentCode:true,timeLimitMinutes:0,deadline:null,antiCheat:false,oneAttemptPerIp:false,maxWarnings:3,shuffleQuestions:true,shuffleOptions:true,showScore:true,showCorrectAnswersAfterTest:false,blockPaste:false,feedbackMode:'end'|'immediate'},questions:[{id,type:'single'|'multiple'|'short'|'matching'|'content'|'truefalse'|'number'|'ordering',text,image:null,points:1,options:[{id,text}],correct: ['optionId'] or string for short or number for number, tolerance?:number, pairs:[{id,left,right}]}],groups:[{id,name,students:[{id,name,code}]}],createdAt,updatedAt}`

True/false questions have exactly two option IDs `true` and `false`, one correct ID, and retain these IDs when cloned. Numeric author values are finite numbers bounded to magnitude 1e15, with nonnegative finite `tolerance` (default0); zero tolerance means exact numeric equality, positive tolerance is absolute. Numeric participant values normalize finite numbers/decimal strings (including comma and exponent) into numbers, while `''` clears a draft. Ordering questions have 2–20 unique option IDs and a `correct` permutation containing every option exactly once; submitted order matters. Ordering options always shuffle at snapshot time, independently of the general shuffle flag. Public question objects omit numeric keys/tolerances and correct ordering. New types support scoring, explicit immediate checks/locks, progress and optional final review.

`feedbackMode` defaults to `'end'`, including quizzes and snapshots created before this field existed. Policy comparisons normalize defaults so an old quiz with attempts can still accept permitted title/deadline edits. Effective immediate feedback requires `feedbackMode='immediate'` and `showScore!==false`.

`showCorrectAnswersAfterTest` is a strictly validated boolean, default false for new and legacy quizzes/snapshots. It controls post-completion review independently of active immediate feedback and score visibility. For terminal participant responses, this field reflects the current quiz permission, so enabling/revoking applies to existing submitted/expired attempts on their next fetch without changing stored snapshots or grades. Previously delivered information cannot be retracted from a client's memory.

Images uploaded via POST /api/admin/uploads JSON `{data: 'data:image/png;base64,...'}` -> `{url:'/uploads/uuid.png'}`. No SVG or external URL. Max image 3MB; body 5MB.

## Admin
GET /api/health -> `{ok:true}`.
GET /api/auth/status -> `{authenticated,setupRequired}`.

POST /api/auth/login `{username,password}` -> `{ok:true}` cookie.
POST /api/auth/logout -> `{ok:true}`.
GET /api/admin/quizzes -> `{quizzes:[quiz summaries with attemptCount,activeCount,onlineCount]}`.
GET /api/admin/live -> authenticated SSE stream, `ready` on connect and `update` JSON `{quizId}` on relevant mutations; periodic keepalive comments. Client refetches authoritative state on connect/reconnect/update, no event replay required. No participant data in event payloads.
GET /api/admin/monitoring -> `{participants:[{kind:'quiz'|'survey',id,attemptId?|responseId?,quizId?|surveyId?,title,slug,name,group?,status,startedAt,expiresAt,finishedAt,presence,warnings?}],summary:{active,online,away,offline}}`. Only active work, no answers, answer keys, private snapshots or historical records. Survey SSE updates carry `{surveyId}` on the same authenticated stream.
POST /api/admin/quizzes `{title?}` -> full quiz object (draft; seeded template questions acceptable).
GET /api/admin/quizzes/:id -> full quiz.
PUT /api/admin/quizzes/:id full quiz -> full quiz; questions, groups, slug, settings, status and prose remain editable after publication and after responses. The server owns `contentRevision` (legacy default1), incremented only when normalized questions change. Existing attempts keep their questions, grading keys, order, roster identity and revision; new attempts use the latest definition. Active snapshots receive new settings; randomized question/option order and checked-answer locks stay fixed. Time limit/deadline recalculate expiry from original startedAt; shortening can expire immediately. Finalized snapshots/results remain unchanged. Name/code requirements affect new starts. Lowering maxWarnings takes effect on the next counted violation, without immediate invalidation. POST /:id/clone remains an optional independent draft; editing does not require a copy. Changing a slug keeps the previous invitation as a server-owned alias: both URLs resolve the same latest form, and a bound participant resumes their frozen work. Aliases reserve names across other forms of the same kind, are cleared on cloning, cannot be forged by client input, and are bounded at200 previous URLs per form.
POST /api/admin/quizzes/:id/clone -> cloned draft.
DELETE /api/admin/quizzes/:id -> `{ok:true}` (requires closed/draft, UI confirm).
GET /api/admin/quizzes/:id/report -> `{quiz:{id,title},summary:{total,submitted,expired,invalidated,active,averagePercent},attempts:[{id,name,group,status,startedAt,finishedAt,expiresAt,ip,warnings,score,maxScore,percent,durationSeconds,events:[{type,createdAt,counted,metadata}],answers}],questions:[{id,text,correct,total,percent}]}`. Consent events have `type:'rules_accepted'`, `counted:0`, `metadata:{language:'ru'|'kk'}` and server UTC receipt time.
GET /api/admin/quizzes/:id/attempts/:attemptId -> `{quiz:{id,title},attempt:{...reportAttempt,questions,review}}`. Administrator only; mismatched quiz or removed attempt404. Questions preserve the attempt's original randomized snapshot, including images and informational blocks. Terminal review includes expected answers and per-question points; invalidated attempts have zero points. Active work has no terminal review. No access cookies/hashes or raw snapshot envelope are returned.
POST /api/admin/quizzes/:id/attempts/:attemptId/retake -> `{ok:true,attemptId,retakeGranted:true}`. Only invalidated attempts, scoped to quiz, authenticated/CSRF protected; repeated grant is idempotent. Grant does not start timer, change result or create a new run. Participant/report attempts expose `retakeGranted:boolean`.
DELETE /api/admin/quizzes/:id/attempts/:attemptId -> `{ok:true}`. Scoped/authenticated/CSRF protected. Deletes only selected active or terminal attempt, its events and archived predecessors; releases its identity/browser/IP reservations. Reservations belonging to other records remain. Old endpoints return404, including writes against a deleted active attempt.
GET /api/admin/quizzes/:id/export.xlsx?variant=public|private -> authenticated Excel; default public, invalid values400. Public workbook has Summary/Attempts/Questions/Events with names, IDs, collected IP, scores/times/warnings, question definitions/options and allowlisted event fields. It contains no participant answers, answer keys, raw metadata, matching mappings or retake history anywhere in the ZIP. Public matching sides/choice pool are separate, ordering options unmarked. Private adds Answers, expected keys, collected UA, event metadata and archived retakes (AttemptHistory/HistoryAnswers/HistoryEvents when present). Two native charts, frozen headers, filters, styled rows and print settings. All user text stays literal strings, never formulas. Filename includes variant. No anonymous/non-authenticated report link exists.
POST /api/admin/quizzes/:id/anonymize -> removes IP/user agent metadata, preserves grades, identity locks and opaque per-quiz IP claims; does not permit retakes. Historical IP metadata already removed before migration cannot be backfilled.

## Participants
GET /api/public/quizzes/:slug -> `{id,slug,title,description,intro,outro,status,settings,questionCount,groups:[{id,name,students:[{id,name,available,requiresRetakeCode}]}],attempt:null|attempt}`. No roster codes or private author keys; an embedded attempt follows the feedback permissions below. Nonpublished unavailable for start. A granted invalidated roster student is available in another browser only if a personal code of at least six characters exists; `requiresRetakeCode=true` requires code input even when ordinary starts do not require it.
POST /api/public/quizzes/:slug/start `{name?,studentId?,code?,rulesAccepted?,language?:'ru'|'kk'}` -> attempt with browser cookie binding. A new anti-cheat attempt requires `rulesAccepted:true`; language defaults to `ru` when omitted. Missing consent or an unsupported new-start language returns400 without creating an attempt. The frontend sends this request only after acceptance in the compact rules modal, so the personal timer starts after acceptance; the calendar deadline still applies. Server records one non-warning `rules_accepted` audit event with the selected language. Existing bound attempts resume without new consent or another timer. UNIQUE(quiz,browser), UNIQUE(quiz,student) ensures first claim, free-name normalized identity uniqueness in quiz. Resume only from bound cookie, never new browser by id/name. Other selected student from same browser must be rejected.

Exception: an invalidated attempt with `retakeGranted=true` can consume its grant at start, requiring current rules consent and a published/nonexpired quiz. The bound browser can omit identity fields; identity is retained. A different browser can consume a roster student's grant only with their correct personal code of at least six characters; a free-name grant stays bound to its browser. A transaction archives prior run snapshot/answers/checks/result/events and keyed IP claim, creates a fresh ID/timer/settings/order, clears warnings and answers, consumes grant and returns201. Concurrent starts from the same browser resume the new run (200) after the first succeeds. Old IDs return404 so delayed events/answers/submission cannot mutate the successor. Archived records are private, linked to the current successor and deleted with it; historical IP reservations continue blocking other participants. Explicit retake is exempt from the IP restriction for this participant.
GET /api/public/attempts/:id -> attempt (bound cookie only).
POST /api/public/attempts/:id/presence `{visibility:'visible'|'hidden',focused:boolean,questionId?:string|null}` -> attempt (bound cookie/CSRF/expiry guards). Independent of warning anti-cheat; never increments warnings. Current question must belong to the attempt. Heartbeat and visibility/focus changes update presence; meaningful changes produce non-warning audit events. Clients send every ~10 seconds, and on visibility/focus/page changes, using keepalive when leaving.
PUT /api/public/attempts/:id/answers `{answers:{[questionId]: string|string[]|{[pairId]:rightText}}}` -> attempt. Server validates question ids/types/options, snapshots answer keys privately at start. content no score. Checked answers cannot change; a changed locked answer returns409 without modifying answers or grades.
POST /api/public/attempts/:id/check `{questionId,answer}` -> attempt. Available only while active in effective immediate mode; checks one scored question, atomically saves and locks the answer, and returns its review under `feedback[questionId]`. Explicit confirmation is required; selecting an option or autosaving never checks it. Repeating the same canonical answer is idempotent; another answer returns409. Multiple-choice order and matching-object property order do not create a new answer. Browser binding, CSRF, expiry and status guards apply; concurrent checks cannot probe alternatives for the same question.
POST /api/public/attempts/:id/events `{type:'visibility'|'blur'|'paste'|'fullscreen',eventId:uuid}` -> attempt. Warning dedupe by eventId; client coalesces blur/visibility into one incident so separate queued offline incidents still count on replay. Only count configured types. Reaching the configured warning limit (default3) immediately finalizes invalidated with zero final score and keeps audit. No answers/grade mutation afterward.
POST /api/public/attempts/:id/submit `{answers?}` -> finalized attempt. A changed checked answer returns409; unconfirmed saved answers are graded normally. Server timeouts enforced every access/write and background sweep, score last autosaved answers; deadline also enforces expiresAt. Submitted/expired/invalidated immutable.

Attempt participant shape: `{id,quizId,status:'active'|'submitted'|'expired'|'invalidated',name,group,startedAt,expiresAt,finishedAt,warnings,maxWarnings,answers,questions:[sanitized question; matching has pairs:[{id,left}],choices:[rightText]],settings,score?,maxScore?,percent?,feedback?,review?}`. Score fields are omitted while active and when `showScore=false`. Quiz removed while active cannot continue. Closed stops new attempts but active may finish. Deadline stops active via expiresAt. Server returns stable randomized order per attempt.

Review item: `{questionId,correct:boolean,points:number,maxPoints:number,expected:string[]}`. Expected values are original-language option texts, the exact short-answer text, or matching pairs formatted `left — right`. In active effective immediate mode, `feedback` maps only explicitly confirmed question IDs to review items. Active end-mode responses omit both `feedback` and `review`. Submitted/expired attempts return `review` only when the current quiz explicitly enables `showCorrectAnswersAfterTest===true` and the attempt's score is visible; it covers every scored question, including those never explicitly checked. Otherwise terminal responses omit both `review` and `feedback`, while ordinary score/percent remain governed by `showScore`. Invalidated attempts expose no new review/feedback. `showScore=false` hides correctness, feedback and review in both modes.

Existing databases receive additive, idempotent `attempts.checked TEXT NOT NULL DEFAULT '{}'` and `events.metadata TEXT NOT NULL DEFAULT '{}'` migrations. Existing quiz documents and attempts are retained; old snapshots without a feedback mode continue in end mode.

## IP restriction and presence

`oneAttemptPerIp` defaults to false. When enabled, one canonical client IP can start only one attempt per quiz, including active/submitted/expired/invalidated attempts. Existing browser resumes its bound attempt before checking the IP restriction. Claim creation/check is transactional, so simultaneous starts cannot bypass the restriction. Claims are recorded even while disabled and backfilled from existing non-null IPs, making later enablement apply to previous attempts. Canonicalization equates IPv6 spelling variants and IPv4-mapped IPv6 with IPv4; it does not collapse an IPv6 subnet or correlate distinct IPv4/IPv6 addresses. Claims use keyed opaque per-quiz digests retained after network-metadata removal, deleted with the quiz. Only explicitly configured trusted `CF-Connecting-IP` overrides the socket IP; forwarded headers are otherwise ignored.

Report attempts additionally expose `presence:{status:'active'|'away'|'offline'|'finished',lastSeenAt,visibility,focused,questionId,answeredCount,totalQuestions,lastAction,lastActionAt}`. After 35 seconds without presence heartbeat an active attempt is offline; visible+focused is active, other connected states are away. Finished attempt presence is finished. Progress counts saved answers to scored questions. Report summary adds online/away/offline. Presence is browser telemetry, not proof of a person's attention. Live notifications also cover saves, checks, warnings, starts, completion and settings changes.

## Surveys and administration routes (23 October 2026)

SPA routes: `/admin` quizzes summary/cards/status filters only; `/admin/surveys` survey list; `/admin/live` combined monitoring; `/admin/reports` combined report center. All clone actions require explicit UI confirmation before POST. Public surveys use `/s/:slug`. Survey views load as a separate client chunk.
Content revision reports: every attempt/response carries `contentRevision`, frozen `title` and `questions`. `revisions[]` contains `{contentRevision,title,questionDefinitions,questions,summary}` for the current definition and revisions represented in work; questionDefinitions preserves full source fields, questions contains per-revision statistics. All work/status totals cover all revisions; question statistics and quiz averagePercent default to the current revision. Older revision statistics remain selectable in quiz reports. Private exports additionally include archived retake-only revisions. XLSX Questions/Options/Attempts/Events and private answer/history sheets identify the revision, using each work's frozen definition; public allowlists still exclude all responses/keys.
Individual reports are full SPA routes: `/admin/quizzes/:id/report/attempts/:attemptId` and `/admin/surveys/:id/report/responses/:responseId`, with back links, questions/answers, metadata and journals. Legacy report `?attempt=...` links redirect without document reload. Only destructive confirmations remain dialogs. General dialogs render through a body portal with a fixed heading and independently scrollable content bounded by the dynamic viewport.
Global UI and Excel default to monochrome. Survey theme colors/logo/cover/font/layout remain author-configurable; previously saved custom themes are preserved. A survey scale uses an accessible range input; its initial visual position is not an answer until the participant deliberately interacts or confirms the displayed value. Explicit zero remains a valid saved answer.

Survey author shape: `{id,slug,title,description,intro,outro,status:'draft'|'published'|'closed',theme:{backgroundColor,surfaceColor,accentColor,textColor,logo:null|'/uploads/...',cover:null|'/uploads/...',font:'sans'|'serif',layout:'card'|'wide'},settings:{anonymous:true,collectName:false,collectIp:false,collectUserAgent:false,oneResponsePerIp:false,oneResponsePerBrowser:false,deadline:null},questions:[{id,type:'short'|'long'|'single'|'multiple'|'dropdown'|'rating'|'scale'|'number'|'date'|'content',text,description,required:false,image:null,options:[{id,text}],min?,max?,step?,minLabel?,maxLabel?}],createdAt,updatedAt}`. Colors are validated #RRGGBB; assets must exist as accepted local uploads. Survey content has no grading keys or scores. Rating/scale use integer bounded steps/ranges, number uses finite bounds/positive step, actual calendar dates required. Drafts may omit required fields; final submission validates them, including numeric0 as answered. Own-property answer lookup prevents prototype IDs from satisfying required questions/progress.

Admin (existing session auth and CSRF apply):

- GET/POST `/api/admin/surveys` -> list `{surveys:[summaries with questionCount,responseCount,submittedCount,activeCount,onlineCount]}` / new draft.
- GET/PUT `/api/admin/surveys/:id` -> full document+responseCount. All fields remain editable after starts/submissions. Question changes increment server-owned `contentRevision`; active responses preserve their frozen questions/revision, while new responses use the latest. Existing active snapshots receive new settings/theme/deadline, finalized responses are not re-opened. Old invitation URLs remain aliases of the same survey; active responses resume after page reload. Aliases are server-owned, collision-checked and cleared on cloning.
- POST `/api/admin/surveys/:id/clone` -> fresh draft, questions/options get fresh IDs, no responses, deadline cleared.
- DELETE `/api/admin/surveys/:id` -> deletes survey/responses/events; published surveys must first be closed.
- GET `/api/admin/surveys/:id/report` -> `{kind:'survey',survey,summary:{total,submitted,active,expired,online,away,offline},responses:[{id,name,status,startedAt,expiresAt,finishedAt,ip,userAgent,collection,answers,presence,durationSeconds,events:[{type,createdAt,counted:0,metadata}]}],questions:[definition+aggregates]}`. Aggregates use submitted responses only: answered/skipped, per-option counts, numeric average/min/max/distribution.
- GET `/api/admin/surveys/:id/export.xlsx?variant=public|private` -> same styled/public allowlist rules. Private includes collected fields, original collection policy and answer aggregates; public excludes responses and aggregates. Anonymous/uncollected fields stay empty even in private exports.
- DELETE `/api/admin/surveys/:id/responses/:responseId` -> scoped removal of work/events/IP/browser claims; stale participant endpoints404, other responses remain intact.

Participants:

- GET `/api/public/surveys/:slug` -> survey+`response:null|own response`, drafts404. Seeds a per-survey HttpOnly opaque access cookie without creating a response or storing identifying metadata.
- POST `/api/public/surveys/:slug/start` `{name?,language?}` -> bound response201, active resume200. No scores or answer keys. Only published/nonexpired new starts. Name required only when nonanonymous collectName=true. Preseeded access credentials make simultaneous starts resume the same response transactionally.
- GET `/api/public/responses/:id` -> own response only, opaque-cookie binding; no cross-browser lookup by ID/name.
- PUT `/api/public/responses/:id/answers` `{answers}` -> validated merged draft; completed409. Autosave never submits or validates missing required fields.
- POST `/api/public/responses/:id/submit` `{answers?}` -> merged required/type-checked immutable submitted response. Subsequent submit returns same result. Deadline enforces expired and denies later edits.
- POST `/api/public/responses/:id/presence` -> same visibility/focus/current-question validation and35s presence semantics as quizzes, without penalty warnings. Journal stores state transitions, not every heartbeat. Consecutive transitions of the same action type still update their action timestamps.

Anonymous mode forces collectName/collectIp/collectUserAgent=false, irrespective of client flags. Disabling collection/turning anonymity on purges the corresponding raw fields from all existing responses; enabling never reconstructs old raw metadata. Per-response `collection` preserves the originally disclosed capture policy+server timestamp; it is not a record of legal consent. Capturing happens only at start. Respondents see collection settings before starting. Free-text personal information is respondent-authored content and is not automatically anonymized.

Optional repeat restrictions store keyed per-survey IP digests and per-survey browser digests only when enabled at start. Claims cover active/submitted/expired work; later enablement cannot infer claims never captured. Normalized IPv4/mapped IPv6/spelling variants are equivalent. Browser resets and distinct IPs remain distinct; shared NAT shares one address. Even unrestricted anonymous responses store a non-identifying access credential for resumption. Rate limiting uses that opaque credential to avoid sharing one classroom budget behind a proxy. With both repeat controls off, a new response may start after completion. Raw metadata is not exposed to participants or live monitoring.

Schema version5 adds `surveys`, `survey_responses`, `survey_events` and indexes with cascading foreign keys. Existing quiz documents, snapshots and results remain intact. Backups include the new tables through the same online backup API.

Both Excel variants also include `Options`, one option/element per row so long allowed option sets are not lost to Excel's cell text limit. Public matching sides remain disconnected there too. Private `AnswerDetails` contains individual selected options/matched pairs (including archived answers); public never includes it. Overview cells may shorten long concatenated lists, while individual rows retain every element.
