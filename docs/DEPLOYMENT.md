# Установка и эксплуатация

Команды выполняются из корня проекта. Один экземпляр Node.js обслуживает SPA и API; SQLite и загруженные изображения хранятся в постоянном каталоге данных. Запуск нескольких реплик с общей базой SQLite не предусмотрен.

## Требования

- Для Docker: Docker Engine и плагин Docker Compose. Node.js на хосте не требуется.
- Для запуска без Docker: Node.js **24.15.0 или новее в ветке 24** и **pnpm 11.25.0**. Версии зависимостей закреплены в `pnpm-lock.yaml`.
- Для публичного доступа: собственный домен и HTTPS через отдельно настроенный reverse proxy или Cloudflare Tunnel.

## Запуск через Docker

Создайте конфигурацию окружения:

```bash
cp .env.example .env
```

Замените `APP_ORIGIN` в `.env` на адрес своего сайта. Origin должен точно совпадать с адресом браузера: схема, имя хоста и порт, без пути.

```dotenv
APP_ORIGIN=https://quiz.example.com
SECURE_COOKIES=true
TRUST_CLOUDFLARE_IP=false
```

Соберите и запустите приложение:

```bash
docker compose build --pull quiz
```

```bash
docker compose up -d --wait quiz
```

```bash
docker compose exec quiz node server/admin-cli.js
```

Последняя команда создаёт первого администратора интерактивно: пароль вводится скрыто и не передаётся в аргументах команды. Разрешена одна учётная запись. Веб-регистрация администратора в Compose отключена через `ALLOW_SETUP=false`.

Compose публикует приложение только на `127.0.0.1:7272` хоста. Настройте HTTPS-прокси или установленный на хосте `cloudflared` на `http://127.0.0.1:7272`; публичный доступ к этому порту не требуется. Для прокси в другом контейнере нужна отдельная конфигурация сети. Прокси должен пропускать длительные SSE-соединения для live-мониторинга.

Проверьте запуск и откройте `/admin` на своём HTTPS-домене:

```bash
docker compose ps
```

```bash
curl --fail http://127.0.0.1:7272/api/health
```

```bash
docker compose logs --tail=100 quiz
```

`TRUST_CLOUDFLARE_IP=true` включает использование заголовка `CF-Connecting-IP` для адресов участников и ограничений по IP. Включайте его только при проверенном доступе исключительно через доверенный Cloudflare Tunnel, который задаёт этот заголовок. Для обычного reverse proxy оставьте `false`: приложение не доверяет произвольным `X-Forwarded-For`.

## Локальная разработка

```bash
npm install --global pnpm@11.25.0
```

```bash
pnpm install --frozen-lockfile
```

```bash
pnpm test
```

```bash
pnpm build
```

```bash
pnpm admin:create
```

```bash
APP_ORIGIN=http://127.0.0.1:7272 SECURE_COOKIES=false  HOST=127.0.0.1 PORT=7272 ALLOW_SETUP=false pnpm dev
```

Откройте именно `http://127.0.0.1:7272/admin`. Если Docker уже занимает порт 7272, сначала остановите его сервис. `SECURE_COOKIES=false` используется здесь только для частного локального HTTP; для публичного запуска оставляйте HTTPS и `true`.

Вместо CLI при первом локальном запуске можно временно указать `ALLOW_SETUP=true` и создать администратора через `/admin`. После этого верните `false`. Веб-настройка доступна только пока администратора нет.

`pnpm dev` запускает Node-сервер с собранным клиентом. После изменения клиентского кода повторите `pnpm build`, после изменения серверного — перезапустите процесс. Прямой запуск Node не загружает `.env` автоматически; передавайте переменные окружения явно. При заданном `DATA_DIR` используйте один и тот же каталог для сервера, CLI, копирования и восстановления. Без Docker по умолчанию это `data` в проекте; в Compose — `/app/data` в volume.

## Обновление и резервные копии

Перед обновлением создайте проверенную копию базы и изображений:

```bash
docker compose exec quiz node scripts/backup.js
```

```bash
docker compose cp quiz:/app/data/backups ./backups
```

Скрипт использует SQLite Online Backup API, проверяет целостность и печатает каталог копии. Не копируйте только работающий `quiz.sqlite`: при WAL часть данных может находиться в соседних файлах. Храните копии также вне сервера; они содержат ответы, учётную запись и сессии, поэтому доступ к ним должен быть ограничен.

После обновления исходников пересоберите и запустите сервис с прежним volume:

```bash
docker compose build --pull quiz
```

```bash
docker compose up -d --wait quiz
```

Не используйте `docker compose down -v` для обычного обновления: флаг `-v` удаляет volume с данными. Сохраняйте предыдущий образ и копию данных до проверки новой версии.

## Восстановление

Остановите приложение и введите имя каталога, выведенное скриптом резервного копирования:

```bash
docker compose stop quiz
```

```bash
read -r -p "Имя каталога резервной копии: " FORMA_BACKUP_NAME
```

```bash
docker compose run --rm --no-deps quiz node scripts/restore.js "/app/data/backups/$FORMA_BACKUP_NAME" --stopped-service
```

```bash
docker compose up -d --wait quiz
```

`restore.js` принимает копии внутри `DATA_DIR/backups`, проверяет их целостность и перед заменой сохраняет прежнюю базу. Флаг `--stopped-service` подтверждает остановку; сам скрипт не проверяет другие процессы. Для нового volume сначала перенесите в него каталог копии. Восстановление возвращает ответы и сессии к состоянию копии; проводите его вне активной сдачи и периодически проверяйте процедуру на отдельном volume.

Для смены пароля используйте существующий логин; текущие сессии администратора завершатся:

```bash
docker compose exec quiz node server/admin-cli.js --reset-password
```

Файлы `.env`, `data`, `backups`, выгрузки и реальные ответы участников не следует включать в публичный репозиторий.
